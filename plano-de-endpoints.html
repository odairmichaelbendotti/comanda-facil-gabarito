01 POST /api/cadastro Criar estabelecimento e conta do dono público

O que faz

Recebe os três passos do formulário de cadastro de uma vez e cria, numa única transação, o registro do estabelecimento e o usuário administrador dono dele. O front valida passo a passo, mas só envia ao apertar "Criar Minha Conta" — por isso é um endpoint só, não três.

Por que é o primeiro: é a única rota que cria um estabelecimento. Sem ela não existe tenant, e todo o resto da API escopa por tenant.

Corpo da requisição

CampoTipoObservação
emailstringVira o e-mail do admin. obrigatório
senhastringMínimo 8 caracteres. obrigatório
tipoDocumento"cpf" | "cnpj"Os dois botões do passo 2. obrigatório
documentostringSó dígitos: 11 (CPF) ou 14 (CNPJ). A máscara é do front. obrigatório
nomeEstabelecimentostringobrigatório
telefonestringSó dígitos: 10 ou 11. obrigatório
enderecostringobrigatório
estadoUFUma das 27. obrigatório

cidadestringopcional — a tela não exige

Resposta 201

{
  "usuario": {
    "id": 1,
    "nome": "Restaurante do Odair",
    "role": "admin",
    "estabelecimentoId": 1
  }
}

Regras

  • Estabelecimento e usuário admin nascem na mesma transação. Se um falhar, os dois voltam atrás — um estabelecimento sem dono é órfão e ninguém consegue entrar nele.
  • O mesmo documento é gravado em dois lugares: estabelecimentos.documento (dado fiscal) e usuarios.documento (credencial de login). Os dois são UNIQUE.
  • A senha é gravada como hash bcrypt em senha_hash, nunca em texto.
  • O cadastro já libera o acesso — nenhuma assinatura é exigida (plano gratuito).
  • Não confirma e-mail: a conta nasce ativa e o token já volta no cookie.
  • O front valida CPF/CNPJ por dígito verificador via MaskedInput; a API precisa revalidar, porque validação de cliente não é garantia.

Erros

400Campo ausente, documento com dígito verificador inválido, UF fora da lista
409Documento ou e-mail já cadastrado

02 POST /api/auth/login Entrar com CPF ou CNPJ e senha público

O que faz

Procura o usuário pelo documento, confere a senha contra o hash e devolve o token no cookie. É o mesmo endpoint para os três papéis — o papel sai do registro no banco, não da tela de onde partiu a chamada. O dono entra com o CNPJ do estabelecimento; o funcionário, com o próprio CPF.

Por que vem aqui: todos os 27 endpoints seguintes exigem token. Sem este, nada mais é testável.

Corpo da requisição

CampoTipoObservação
documentostringSó dígitos, 11 ou 14. obrigatório
senhastringobrigatório

Resposta 200

{
  "usuario": {
    "id": 2,
    "nome": "Carlos Silva",
    "role": "garcom",
    "estabelecimentoId": 1
  }
}

Regras

  • A mensagem de erro é idêntica para documento inexistente e senha errada, para não revelar quais CPFs/CNPJs estão cadastrados. A tela já faz isso ("CPF ou senha inválidos").
  • Usuário com ativo = false ou deleted_at preenchido não entra, mesmo com a senha correta.
  • O token vai em cookie httpOnly, Secure, SameSite=Lax. O corpo devolve só os dados do usuário.
  • O payload carrega estabelecimentoId — é ele que escopa todos os outros endpoints.
  • Limite de tentativas por documento, para travar força bruta.
  • O tipo de documento escolhido na tela é só conveniência de máscara; a API procura pelo número, não pelo tipo.

Erros

401Credenciais inválidas
403Conta desativada
429Tentativas demais

Pendências

  1. Os mocks do front usam chaves em inglês; o banco, em português. As telas trabalham com { name, price, category } e { name, qty, price }, e o NewProductModal ainda manda o nome da categoria como valor do select, não o id. O schema Prisma usa nome, preco, categoriaId. Adotei o lado do Prisma no contrato acima, mas alguém precisa renomear no front — ou inverter a decisão. Afeta praticamente todo endpoint.
  2. Cancelar não tem botão. O status existe no enum e no filtro, e a regra ficou decidida (admin e garçom, até ficar pronto), mas o OrderDetailModal não tem esse botão. Bloqueia o endpoint 27 na prática.
  3. Editar pedido é um TODO. app/pedidos/page.tsx:264 só fecha o modal. Falta a tela de edição — provavelmente reaproveitando o NewOrderModal com valores iniciais. Bloqueia o endpoint 24.
  4. produtos.disponivel não tem controle na tela. A coluna existe, o endpoint 13 está desenhado, mas nada em /produtos liga ou desliga.
  5. usuarios.ativo também não. A tabela de /funcionarios mostra o badge Ativo/Inativo, mas o FuncionarioModal não tem esse campo — não há como desativar alguém pela interface. Deixei como campo opcional do endpoint 19.
  6. Telefone do funcionário é exibido mas nunca coletado. A coluna aparece na tabela e app/funcionarios/page.tsx:219 cria todo mundo com phone: "". Ou o modal ganha o campo, ou a coluna sai da tabela.
  7. Ninguém recupera a própria senha. Funcionário não tem e-mail no cadastro, então não há canal — a redefinição só acontece pelo admin no endpoint 19. Para o admin, que tem e-mail, não existe fluxo nenhum: se ele esquecer a senha, perde o estabelecimento. Exigiria a tabela de tokens que decidimos não criar.
  8. Stripe não tem tela. A landing promete "Ver Planos e Preços" e o botão não leva a lugar nenhum. Sem uma rota /planos, os endpoints 28 e 29 não têm por onde ser acionados.
  9. A paginação do front é local. usePagination fatia um array em memória e o pageSize vem do viewport via useResponsiveGrid. Para consumir ?page=&limit=, o front precisa mandar o tamanho calculado e refazer a busca a cada troca de página — hoje ele só re-renderiza.
  10. A tela da cozinha não se atualiza sozinha. Não há polling nem realtime em /pedidos. Um pedido lançado pelo garçom só aparece para a cozinha se alguém recarregar a página — o que inviabiliza o fluxo na prática. Decidir entre consulta periódica, SSE ou websocket muda o desenho do endpoint 22.
  11. A sessão do front não carrega o estabelecimento. AuthUser em app/lib/store/auth-store.ts guarda só { id, name, role }. Num sistema multi-estabelecimento falta estabelecimentoId, que os endpoints 01, 02 e 03 já devolvem.
  12. Tipo do id diverge. Os mocks usam string (id: "1", id: "coca-cola") e o banco usa Int autoincremento. O JSON vai trazer número; o front precisa parar de comparar com string.
